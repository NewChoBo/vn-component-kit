# Choice authoring contract

선택지는 기획서의 상태 분류를 묻는 설문이 아니라, 장면 속에서 플레이어가 다음 행동을 결정하는 순간이다.

## 작성 템플릿

```yaml
id: scene-choice-id
ariaLabel: 화면 낭독기에 전달할 선택의 목적
situation: 지금 인물이 보고 듣고 느끼는 구체적인 상황
constraint: 모든 행동을 동시에 할 수 없는 이유
question: null # 문맥만으로 충분하면 생략
options:
  - id: stable-option-id
    label: 현재형 동사로 시작하는 실제 행동
    description: 플레이어가 지금 알 수 있는 의도 또는 즉시 비용
  - id: another-option-id
    label: 첫 선택지와 평행한 문법의 실제 행동
    description: 플레이어가 지금 알 수 있는 의도 또는 즉시 비용
```

## 문장 규칙

- 선택 전에는 현재형을 사용한다.
- `무엇을 우선했는가`, `어떤 행동을 했는가`처럼 이미 결정된 일을 평가하지 않는다.
- `무엇을 우선할까`보다 시간, 위험, 자원 같은 실제 제약을 먼저 보여 준다.
- prompt가 없어도 선택지가 자연스럽게 이어지면 질문을 생략한다.
- option은 `확인한다`, `남는다`, `숨긴다`처럼 관찰 가능한 행동으로 쓴다.
- option끼리 시제, 시점, 문장 길이와 추상화 수준을 맞춘다.
- 결과를 미리 폭로하지 않지만 플레이어의 의도와 즉시 trade-off는 속이지 않는다.
- 내부 state key, route 이름, good/bad 등급을 표시 문구에 사용하지 않는다.

## 검수 체크리스트

- 클릭 전인데 과거형으로 묻고 있지 않은가?
- 상황과 제약만 읽어도 선택 기준을 이해할 수 있는가?
- 모든 option이 실제로 다른 행동을 약속하는가?
- 선택 결과가 표시된 의도와 모순되지 않는가?
- 선택하지 않은 option도 명백한 오답이나 콘텐츠 포기로 보이지 않는가?
- 모바일에서 2~4개 option을 한눈에 읽을 수 있는가?
